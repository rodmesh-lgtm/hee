# Subscriber packages and cashier integration

The accounting workspace supports reusable, tenant-owned **monetary credit and counted service packages** for any business activity. The service catalogue determines package scope. Monetary package price equals prepaid credit; counted packages use purchased unit entitlements as detailed below. No VAT is added.

Owner defines a name, description, price, duration (1–366 calendar days in Riyadh), and service IDs. Monetary packages may leave service scope empty to include all services; counted packages require exactly one service. Accounting-permission staff enrol registered customers and choose a start date. Each enrolment snapshots the purchased name, description and services. Archiving a package prevents new sales but does not revoke existing benefits. Create a new package version to change terms. Renewals are new purchases; prior balances remain intact.

On cashier phone entry the authenticated, no-store lookup returns this tenant's customer balances. The cashier previews coverage and remaining balance. Saving the order atomically allocates valid balances by earliest expiry, limited to eligible line values and the amount outstanding after new cash/card collections. The submitted preview amount must match the authoritative allocation; stale previews roll back the entire order. A tenant transaction lock, order request replay, unique movement/payment request keys and ledger source keys prevent duplicate deductions. Each deduction posts a prepaid payment and liability settlement, not a second cash receipt. Opt-out is explicit in the order form.

Manual monetary redemption remains available to accounting staff. Restricted monetary packages can manually settle only orders wholly within their service scope; mixed-scope orders must use the automatic allocation at creation. Expired balances cannot fund an order but remain refundable under the existing refund flow. Refunds record money actually returned; no bank transfer or neoleap request is sent.

Apply migration `20261022200000_accounting_packages` using the existing reviewed migration workflow **before deploying** this version. It adds AccountingPackage and additive fields on LaundryPrepaid; it preserves original balances and backfills startsAt from createdAt. It does not modify platform billing subscriptions or the separate Salla automation draft.

Limits: the current catalogue lists the latest 200 package definitions; the subscriber list and cashier lookup show up to 100 records. No automatic renewal charge, multi-service counted bundles, automatic subscription WhatsApp messaging or live neoleap integration is included. The existing ready-order notification integration is separate.

Verification includes domain tests for service restrictions, split coverage, expiry and Riyadh dates, plus the existing browser transaction scenario extended with package creation, enrolment, archival, automatic partial-cash redemption, replay and tenant-isolated lookups.

## Counted service packages (2026-10-23)

- The owner selects monetary credit, pieces, or service visits. A counted plan has one explicit service and 1–10,000 units. Each ordered quantity of that service consumes one unit; a visit is **not** an unlimited multi-item order. Bundles with several different service entitlements are not supported in this version.
- Counted entitlements are applied before monetary credit, earliest expiry first. Uncovered quantities keep catalogue prices. Covered quantities are priced at their proportional share of the purchased package, preserving prepaid liabilities and delivery revenue. Integer halala rounding is carried into remaining value; receipt rows split if necessary so quantity × unit price always equals the row total.
- Cash/card collections pay uncovered services only. Preview shows the resulting order total, balance, and remaining units. Authoritative transaction recomputes the quote under the existing tenant lock and rejects a stale allocation token. Counted requests require that token; older monetary requests retain compatibility.
- Renewal creates a separate balance. Archival does not remove purchased benefits. Existing-order manual monetary redemption rejects counted balances. Refund of a counted balance requires its full unused monetary value and closes all remaining units; partial counted refunds are not offered.
- Additive migration `20261023090000_accounting_counted_packages` leaves existing credit balances unchanged and constrains counts, service scope, and monetary remainder. All new fields are read from authenticated tenant-scoped paths.
- Tests cover rounding, multiple renewals, eligibility, expiry, mixed credit/cash, replay, stale quote rollback, counted refund, and liability reconciliation. Production test transactions must not be used.
